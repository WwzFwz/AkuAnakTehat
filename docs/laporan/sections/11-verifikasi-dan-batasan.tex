\subsection{Ketahanan ukuran event dan pemulihan}
Pengujian PostgreSQL menerima envelope 4 MiB dikurangi satu byte serta tepat 4 MiB, mengarantina envelope yang melebihi batas satu byte, dan tetap memproses record berikutnya. Backlog 600 record diuji dengan kegagalan di tengah respons. Checkpoint tidak maju saat gagal dan pengulangan tidak menghasilkan outbox ganda.

Pengujian lintas service mengalirkan event 4 MiB utuh melalui relay, Kafka, ketiga consumer, dan API menggunakan fixture administratif. Pengujian penyimpanan SQLite memeriksa bahwa kegagalan storage tidak memindahkan event valid ke DLQ atau memajukan offset sebelum pemulihan. Hasil ini mendukung mekanisme retry dan pemulihan pada skenario yang diuji, dengan batas retensi serta semantik pengiriman pada Bagian~\ref{sec:p5}.

\subsection{Verifikasi instrumentasi HTTP}
Client API mencatat satu log \texttt{upstream\_request} untuk setiap pemanggilan \texttt{HTTP.Do} oleh adapter. Timer dimulai ulang pada setiap percobaan dan mencakup pembacaan, decode, serta penutupan body respons. Log memuat correlation ID, nomor percobaan, latency, status HTTP, dan kategori hasil. Status 0 menunjukkan respons HTTP belum diperoleh. URL, kredensial, isi respons, dan pesan galat upstream tidak dicatat.

\texttt{TestRetryLogsEachAttempt} menggagalkan percobaan pertama lalu memberikan respons valid pada percobaan kedua. Tes memeriksa dua log dengan nomor 1 dan 2, correlation ID yang sama, hasil transport error diikuti sukses, serta deadline yang tidak diperpanjang. Tes lain memeriksa batas retry, pembatalan, timeout, respons invalid, dan penutupan body. Seluruh tes module Client API dan go vet lulus. Temuan U7 tentang latency retry yang tergabung telah ditutup melalui pengujian ini.

\subsection{Bootstrap pada volume kosong}
Pengujian mengekstrak source commit ke direktori terpisah tanpa konfigurasi lokal lama. Bootstrap membuat 12 berkas konfigurasi dan kunci baru; pemanggilan kedua mempertahankannya tanpa rotasi. Project Compose memakai network tersendiri serta enam volume yang belum ada sebelum pengujian.

Migrasi mencapai versi 3 dengan status dirty false. API menyajikan 42 hazard dengan kedua sumber HEALTHY, dan permintaan raw oleh Media ditolak dengan 403. Dashboard serta Pemda masing-masing menerima 42 snapshot. Notifier mencatat 46 pemrosesan karena hazard dapat mempunyai beberapa versi. Ketiganya mencakup seluruh ID hazard yang diperiksa pada Canonical Store. Rincian hasil tersedia pada \finalevidence{bootstrap/result.json}.

Setelah pengujian, volume project uji dibersihkan dan stack utama dijalankan kembali. Pemeriksaan memastikan volume, isi kredensial, dan satu hazard acuan stack utama tetap tersedia. Uji ini membuktikan startup dengan data persisten kosong dan konfigurasi baru pada host yang sudah memiliki Docker serta cache build; bukan instalasi host dari nol.

\subsection{Cakupan bukti dan pemeriksaan akhir}
Regresi stack dan load test dijalankan pada implementasi \texttt{a465139}, yang sudah mencakup instrumentasi latency per percobaan HTTP. Tes module Client API memeriksa cabang retry secara terarah, sedangkan regresi dan k6 memeriksa perilaku stack setelah dibangun ulang. Masing-masing artefak tetap dicatat menurut cakupan pengujiannya.

Regresi dan load test memakai volume stack utama, sedangkan bootstrap diverifikasi terpisah pada enam volume kosong. Selain skenario outage 20 detik, pengujian tambahan telah menjalankan outage 600 detik dengan recovery 90 detik dan memeriksa pemulihan tanpa restart. Pengujian satu host juga belum membuktikan failover lintas mesin atau kapasitas deployment lain.

Pemeriksaan secret menggunakan Gitleaks tidak menemukan temuan pada histori hingga \texttt{2353479}, dengan bukti pada \reliabilityevidence{secret-scan.txt}. Scan revisi pengumpulan dan verifikasi CI hosted tetap diperlukan sebelum penyerahan. Status kelengkapan persyaratan tersedia pada \codepath{docs/requirements-audit.md}.
